## 2026-07-27 - [Performance Optimization] O(N*M) nested array lookups in Render Phase
**Learning:** Found O(N*M) performance bottlenecks in `HeroCarousel` slides due to `.map()` looping over arrays and performing `.find()` lookups on another unindexed array inside the callback. Because this was unmemoized, it caused repeated O(N*M) iterations across large product arrays on every re-render. Additionally, learned that `pnpm run pages:build` can sometimes fail with a V8 OOM error, and that `tsc --noEmit <file>` is a reliable fallback for fast local typechecks.
**Action:** When finding multiple `.find()` calls on the same array inside a `.map()`, pre-compute a `Map` outside the loop to reduce lookup time from O(N) to O(1). Wrap these transformations in `useMemo` so the work is only done once when dependencies change, preventing memory thrashing and unnecessary re-renders. Use `tsc --noEmit` on modified files if full Next.js builds OOM.

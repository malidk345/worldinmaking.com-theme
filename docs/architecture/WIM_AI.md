# WIM AI architecture
Canonical map of WorldInMaking AI as implemented in malidk345/worldinmaking.com-theme.

## Two products, one orchestrator
- Workspace Ask AI: `src/pages/api/chat.ts` (Edge SSE) -> `streamBotTurn` in `src/lib/bots/orchestrate.ts` with tools on.
- **Abort / Stop**: client `AbortController` cancels `fetch('/api/chat')` (Stop button, Meta+., unmount/close, chat switch). Edge `req.signal` + stream `cancel()` abort the turn and linked provider fetches in the tool loop.
- Forum / philosopher / paper: `src/pages/api/bots/act.ts` and `src/pages/api/philosopher-bot.ts` -> `runBotTurn`, tools off.
- `src/lib/bots/index.ts` re-exports the orchestrator. Do not add a second generation path.

## Workspace chat turn
1. POST `/api/chat` (runtime=edge). Prompt max 8000 chars. Default persona `nietzsche`.
2. Supabase auth via `getSupabaseUserFromRequest`. Guest vs member vs Pro.
3. Quotas (skipped in local/dev): weekly token budget (resetting UTC Monday). Guest 80k / member 2.5M / Pro 20M (`src/lib/token-quota.ts`). Tools share the same weekly token bucket: a successful turn records an estimate of the visible text (prompt + context + history + reply + streamed thinking, ~3.6 chars/token) plus, per executed tool call, the streamed tool arguments/results estimate and a flat 2,000-token surcharge (`estimateToolSurchargeTokens`). Tool calls are counted in `/api/chat` from the `onTool` stream (`src/lib/tool-usage-meter.ts`): top-level, `task` sub-agent (task + nested reads), host live-web search, errored calls and cached research repeats all count; a call is counted once per running→finish cycle; #844 answer recovery is tools-off and adds nothing. Failed / aborted turns record nothing. The estimate does not include the provider-side system prompt, tool schemas or per-round re-sent history. BYOK turns skip `recordTokenUsage`. In-memory token tracking is only the fallback when Upstash creds are absent.
4. User context is labeled untrusted (systemPrompt, notebook, scratchpad, attachments, history). Notebook/document retrieval is lexical (keyword/TF + host snapshot tools), not embedding/vector RAG; empty matches fail closed — do not invent notebook citations.
5. BYOK payload `body.byok` (groq|gemini|openai|anthropic) overlays provider env for that turn only.
6. Tools: `runToolLoop` in `src/lib/bots/tools/`. Graph `pipeline.ts` (THINK / ACT / TOOLS), max 16 steps. Public text only when an ACT round has zero tool_calls.
7. SSE: mode, token, tool, node, human, checkpoint, citations, artifacts, token_usage, done or typed error. Heartbeat 15s.
8. If live web is needed and the model skipped web_search, the host runs Tavily. No invented headlines.
9. Prior-turn citations: the client sends `priorCitations` (`src/lib/ai/prior-citations.ts`: newest reply wins on id clashes, max 20 entries, title 160 / author 60 / URL 300 chars; each entry id, kind, title, first author, year, DOI/URL, turnsAgo). `/api/chat` re-sanitizes it (`parsePriorCitations`), adds a compact untrusted context block (≤3,000 chars) so "tell me more about P3" resolves, and passes it through orchestrate → loop → pipeline into `ToolExecutionContext.priorCitations`. `related_papers`, `find_quotes` and `bibliography` fall back to a prior-turn [P#] only when it is not in this turn's list; they re-fetch by DOI / S2 / OpenAlex id (web pages are refused), so the prior entry is a lookup key, never a trusted citation.

`runBotTurn` runs `applyQualityGate`. The `streamBotTurn` tool-loop success path also applies the quality gate. Host fallback copy from the tool loop (`ToolLoopResult.fallback`: honest "could not finish" message or the generic action confirmation) skips the quality gate and carries no `qualityGate` flag, so the critic can never rewrite it into persona prose. When the post-tool answer round fails or comes back empty, `loop.ts` retries the answer once, tools off, on the next key/model in the chain from the tool results already gathered (`tools/answer-recovery.ts`), then falls back to a short localized (TR/EN) message while keeping the source cards; failures log `[tools] answer round failed` / `[tools] answer synthesis retry` / `[tools] candidate failed` (status + redacted provider detail, no content).

## Agent modes and tools
`src/lib/bots/agent/modes.ts`: ask | plan | execute. Plan locks mutating OS tools (artifacts, notebook writes, windows, appearance, forum publish). Research, todo_write, ask_user, finalize_plan stay on. ask_user pauses via checkpoint.ts / human.ts.

Wire format: OpenAI Chat Completions functions (`src/lib/bots/tools/spec.ts`). Groq native, Gemini adapter. Loop families in loop.ts: groq, gemini, nvidia, openai, anthropic. Tool budget ~45s vs gateway ~28s. Host THINK is a short routing note (`THINK_MAX_TOKENS` 256, no Gemini native thinking on that round). ACT keeps `max_tokens` 8192 and gpt-oss `reasoning_effort: low`. `create_artifact` canvas/3d/sim JSON is fail-closed; canvas nodes without x/y get an auto-grid; same title revises the open card. HTML preview is `sandbox="allow-scripts"` only. Ask AI quality-gate outage keeps the streamed reply (`skipped`). React/HTML screens must use host chrome (`bg-primary` paper, `bg-navy` actions) and fill the window — not toy landing pages. `search_academic_corpus` merges and ranks OpenAlex/Crossref/S2 (+ arXiv for STEM, PMC/Europe PMC for biomedical) by query match + citations + OA PDF, reports per-source status (all-failed = `ok:false` degraded, not "no literature"), and returns one `[P#]` line per paper; optional keys `OPENALEX_API_KEY`, `SEMANTIC_SCHOLAR_API_KEY`, `NCBI_API_KEY`. Step 2 adds keyless TR Dizin (Turkish), CORE + DOAJ (humanities / OA), SEP + IEP encyclopedia entries for philosophy (title + link + ≤ 300-char excerpt), optional `query_original` for bilingual fan-out, reciprocal-rank fusion with a relevance floor, a shared `caches.default` cache (search 3 d, DOI 30 d), and a post-answer citation check that flags unverifiable references (`verified:false`) without rewriting the answer. Step 3 adds `related_papers` (citation graph: S2 citations/references/recommendations, OpenAlex references/related/cited-by, OpenCitations, Crossref reference lists; keyless it degrades and names the missing key), opt-in `find_quotes` (short verbatim passages with location from S2 snippets [key], Europe PMC / CORE full text or the OA PDF via `read_document`; never paraphrases as quotes), and `annotated_bibliography` (APA from real metadata only, optional insert into the bound notebook); `[P#]` ids stay turn-global across all three (`[P@n]` = already-cited source). Citation hygiene (package B): every academic tool result — also with zero new citations and inside `task` sub-agents — goes through `mergeToolCitations`, so the model never sees `[P@n]`, a source already cited this turn (DOI / title / URL, e.g. a repeated or cached search, a SEP entry found twice) keeps its id instead of adding a duplicate card, and sub-agents may use `related_papers` / `find_quotes`; the UI still renders a stray `[P@n]` as a normal marker, and plain `[n]` inside code or glued to an identifier (`arr[5]`) is neither linked nor counted as verified. A DOI in the query (or in `query_original`) is resolved via Crossref + Unpaywall and listed first (a bare DOI returns only that work). Retracted works / retraction notices (Crossref `updated-by` / `update-to`, OpenAlex `is_retracted`, PubMed / Europe PMC type, "RETRACTED:" titles) are dropped by default and always under `open_access_only`; only a query about retractions keeps them, last, with a "Retracted" tag on the card. APA output keeps up to 20 authors (21+: first 19 … last), organisations verbatim and name particles, and never adds a period after `?` / `!`. The post-answer DOI check aborts its Crossref requests when its 4.5 s budget ends. Uploaded PDFs keep `[Page N]` markers (cap 200); `read_document` slices those pages. Scanned PDFs report no text — no OCR. Remote PDFs (package E3): `read_document` and `find_quotes` decode PDFs with `unpdf` (serverless pdf.js, lazy-imported) via `src/lib/bots/pdf-text.ts` — compressed / object-stream PDFs (e.g. DergiPark) now yield text, `[Page N]` are real PDF page numbers, and a consistent printed pagination is detected (`p. 132 (PDF page 2)`). Caps: 12 MB download (streamed, larger PDFs are refused), 60 pages, 400k chars, 8 s extraction budget; PDFs pdf.js cannot open (or finds no text in) fall back to the old `BT…ET` byte scan (first 500 KB) of the same download — `find_quotes` never fetches a PDF twice — and HTML keeps the 500 KB window. `find_quotes` searches every extracted page (not just the first 12k chars) and labels quotes with the page; `read_document` output is still capped at 12k chars.

Citation styles and export (package E1/E2): `src/lib/ai/citation-styles.ts` formats APA 7 (default, unchanged `formatApaReference`), MLA 9 and Chicago author-date (reference list) from the same metadata and the shared name parser (`parsePersonName`: organisations, particles, suffixes, Turkish names; MLA 3+ authors → "et al.", Chicago 11+ → first 7 "et al."; MLA / Chicago titles in headline case for English, unchanged for Turkish and other languages). The user's choice lives in `localStorage` `wim_citation_style_v1` (`src/lib/citation-style-pref.ts`, never Supabase) and applies to the Sources panel Copy button, "Add to notebook", whole-reply footnotes and — through `citationStyle` in the chat request → `HostSnapshot.citationStyle` — the `annotated_bibliography` default (its `style` argument, set only when the user names a style, wins). `src/lib/ai/citation-export.ts` writes BibTeX (article / book [publisher] / incollection / phdthesis / misc for web + encyclopedia, stable `author+year+word` citekeys deduped a/b/…, BibTeX specials escaped, organisations braced, acronyms protected, Turkish kept as UTF-8, 21+ authors "and others") and RIS (CRLF, JOUR / BOOK / CHAP / THES / ENCYC / ELEC / UNPB / GEN, UTF-8 BOM for EndNote). Export is client-side only: the Sources panel toolbar (style selector + BibTeX / RIS for every verified source of the reply) and the notebook Export panel (BibTeX / RIS of the notebook's footnotes and References / Bibliography / Works Cited / Kaynakça sections, parsed by `src/lib/notebook-references.ts` and, for DOIs, refreshed from Crossref in the browser — ≤ 40 lookups, 4 at a time, 6 s each, parsed text kept on failure).

Academic tool routing (package E4): the `related_papers` / `find_quotes` descriptions lead with the explicit asks they serve (papers citing X / what X cites / similar papers; exact quotes / page evidence), and `src/lib/bots/academic-routing.ts` adds one context line ("Tool routing (the user explicitly asked): …") only when the user's message matches those asks in English or Turkish — ordinary turns pay nothing. Similar-paper results drop front matter / errata / peer-review / dataset records from every list, keep a similar-only work only when it overlaps the seed topically (2 shared title/abstract stems, or 1 stem + a shared OpenAlex topic, or 2 shared topics across languages; 1 stem when the seed has only a title) and rank similar works by that overlap; when OpenAlex has no `related_works` for the seed, the most-cited works of the seed's primary OpenAlex topic are used (then filtered). S2 recommendations are used as before (keyless when S2 allows, keyed otherwise).

fetch_url (`tools/fetch-url.ts`): http(s) only, up to 3 redirects with hop-by-hop SSRF (same policy as `read_document`), 8s, 200KB, blocks localhost / private IPv4 / metadata / .internal. IPv6 hostnames refused. `posthog-analytics` is a live artifact kind; do not rename as cleanup.

## Security and BYOK
Keys live in the browser (`localStorage` `wim_byok_vault_v1` in `src/lib/byok-vault.ts`). They are not stored server-side. They do transit to the Cloudflare edge via the chat request body (`body.byok`) for that request. `/api/byok/verify` is a 1-2 token probe, not persisted. Vault providers are groq, gemini, openai, and anthropic. Anthropic is included in TOOL_FAMILY_ORDER.

SECURITY_PREAMBLE in orchestrate.ts. Mutating `/api/bots/act` needs CRON_SECRET / BOT_ACT_SECRET. Chat action does not. Rate limit 500/hour per IP. Chat fails closed on provider outage (PROVIDER_UNAVAILABLE).

## Philosophers
PHILOSOPHER_BOTS in src/lib/persona-engine.ts matches BOT_ROSTER in src/lib/bots/philosopher-tick.ts (16 bots, default Nietzsche).
/api/philosopher-bot is runBotTurn, no tools.
/api/bots/act actions: chat, forum_reply, thread_init, paper_step, status.
Paper steps: thesis, antithesis, cross_examine, third_voice, synthesis.
/api/philosopher-bots lists Supabase bot_profiles.
Hourly forum is GitHub Actions .github/workflows/philosopher-bots-cron.yml. Edge does one plan or one LLM+persist. RSS is not fetched on the edge.

## Gateway and quotas
ai-gateway.ts: Groq and Gemini rotate. About 28s total, 9s failover. Groq 8k TPM. Skip Groq if prompt is over about 6500 tokens.
Workspace chat weekly token quota (`failClosed: true`). Memory isolate is used only when Upstash is not configured. Tool loop budget ~45s vs gateway ~28s. Chat fails closed on provider outage (`PROVIDER_UNAVAILABLE`) and on quota store outage (`QUOTA_UNAVAILABLE`).

## Chat persistence (guest vs signed-in)
Local-first: IndexedDB + localStorage write-through (`chat-local` / `chat-remote`). Cloud push/pull/realtime/12s poll requires a signed-in session (`canSyncChatsToRemote`). Guests stay local-only; on login, `adoptGuestChatsIntoAccount` + `claimDeviceAccountOnLogin` + `pushDirtyLocalChats` move device chats onto the account (notebook parity with `canSyncNotebooksToRemote`).

## Notebook bridge (chat ↔ notebook)
- Chat → notebook inserts go through `dispatchNotebookOsEventWithAck` (`src/lib/notebook-os-dispatch.ts`): every event carries a `requestId`; the chat waits for the notebook's ack/nack echoing it (4–5 s) and reports `not_reachable` / `timeout` / the nack reason honestly. "Added" is shown only after a real success ack. Only one editor instance claims an event (`src/lib/notebook-os-claim.ts`).
- "Add to notebook" with no editor open: `resolveNotebookAddTarget` (`src/lib/notebook-add-target.ts`) picks the bound/open notebook, else the most recently updated real notebook (templates and the seeded intro are skipped), else creates "Research Notes" through the normal `createNotebook` path; the editor is opened with the deduping `openNotebookWindow`, and adds are queued so rapid clicks never open extra windows.
- Duplicate sources (same DOI, normalized URL, or long title already in the note) are nacked `duplicate_source` → "Already in this notebook".
- Whole-reply Add converts [P#] / [n] / [Source n] markers into notebook footnotes with reference definitions in the user's citation style (APA by default; `citationMarkersToFootnotes`); inserted footnotes are renumbered after the note's own, and a definition already in the note is reused. Insert composition is text-level; the rest of the note is not re-serialized.
- `insert_notebook_block` limit is 20,000 chars (cut at a paragraph boundary, `truncated` reported); the `bibliography` tool may use up to 40,000. Its result is an offer card — the tool reports `added_to_notebook: false, notebook_insert_offered: true`, and the model must not claim it was added.
- Sticky notebook selection is tied to its notebook, cleared when the selection collapses inside the editor and after one use; a live selection always wins.
